# Flyover Atlas

Build a local Python tool that estimates where a recording was made by matching aircraft tones in its audio to historical flight tracks. The result is a ranked map of possible microphone locations, with a spectrogram overlay that shows how well each flight fits. Use Colsto’s public challenge clip or a recording you made at a known location as a benchmark. The transcript explains the method. Reproducing the result requires the original audio and corresponding flight tracks. [Video demonstration](https://www.youtube.com/watch?v=UytYrhYLOKI)

## Build order

`Known-location overlay → timed single-event search → unknown-start two-event search → validation → wider search`

Start with one local CLI, files on disk, and QGIS for viewing results. Use FFmpeg for decoding, Python with NumPy and SciPy for signal processing and geometry, and Matplotlib for plots. Add PyProj and a DEM reader when introducing real geographic coordinates and terrain. Use CSV or compressed NumPy arrays for the first flight dataset. Move to partitioned Parquet with DuckDB when dataset size makes filtering or loading expensive. See the [implementation checklist](todo.md) for dependencies and acceptance checks.

### 1. Get a benchmark and prove the data is usable

- Choose an unedited clip with a distinct flyover, known microphone coordinates, and a trustworthy UTC start time. If recording your own clip, stay at a fixed position, keep the original audio, and record the start time and approximate microphone height separately. For the public challenge, start with a small region around its published location to test the pipeline. Keep exact coordinates out of the search inputs once the overlay works.
- Cache a few continuous 3D tracks from the same region and time, with enough padding for sound travel and the wings of each flyover. Confirm coverage, sample gaps, altitude fields, and source terms before buying data or planning a large run. An archived ADS-B position or state-vector dataset is the input. Flight summaries with only departure and arrival times are inadequate. [OpenSky historical data documentation](https://openskynetwork.github.io/opensky-api/trino.html) · [OpenSky sample datasets](https://opensky-network.org/data/scientific)
- Optional shortcut for reproducing the demo. Use the MIT-licensed `dopplertrack` implementation on the same input. Its documented flow goes from `spectrogram` and `fit` to `fetch`, then `search --point` for a known-position overlay or `search --bbox` for a regional run, followed by `refine`. Pin the version and save inputs and outputs so it can serve as a baseline. Its authors report a best point 32 m from the public challenge camera with additional flyovers and an ambiguous verdict using only two events. They also document a recording whose true pair never won. [dopplertrack README](https://github.com/mjshiggins/dopplertrack) · [Experiment log](https://github.com/mjshiggins/dopplertrack/blob/main/docs/experiments.md)

### 2. Extract a Doppler curve from the recording

- Decode PCM audio from the original media and confirm the selected stream, duration, sample rate, channel, and the UTC time corresponding to the first decoded sample if known. For a video with one relevant audio stream, a starting command is `ffmpeg -i recording.mp4 -map 0:a:0 -c:a pcm_s24le recording.wav`. Check individual channels if one is cleaner. Preserve the original and document any cut or discontinuity. [FFmpeg stream selection](https://ffmpeg.org/ffmpeg.html#Stream-selection)
- Compute a short-time Fourier transform (STFT) and export a heatmap. Inspect roughly 60–400 Hz as a starting band, using a Hann window of about 2–4 seconds and a hop of about 0.1–0.25 seconds. Adjust the window if ridges blur during a rapid transition. Subtract a per-frequency background level in log power to reduce steady hum. Keep the raw spectrogram available for comparison. [SciPy ShortTimeFFT](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.ShortTimeFFT.html)
- Mark a time and frequency window around a smooth falling ridge. Trace it by hand for the first pass and use visible harmonics as a cross-check. Fit a straight, constant-speed flyby to obtain rough bounds for speed, closest 3D distance, emitted frequency and audio time of closest approach as heard. Leave broad bounds when only half the ridge is visible or the aircraft is maneuvering. Treat a traced harmonic as its own emitted tone, or label its harmonic number when fitting a common fundamental. [SciPy bounded and robust least squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)

### 3. Make flight geometry predict what the microphone heard

- Normalize the tracks to UTC seconds and metres. Sort and deduplicate positions, segment flights at major gaps, and avoid scoring across unsupported times. For a regional search, convert tracks and microphone candidates to the same local east–north–up frame. Use a digital elevation model (DEM) for candidate ground height and add microphone height if known. Reconcile vertical references before subtracting heights. Document barometric altitude as an approximation if no reliable geometric height is available. [OpenSky state vector schema](https://openskynetwork.github.io/opensky-api/trino.html) · [USGS 3DEP datum and resolution](https://www.usgs.gov/faqs/what-projection-horizontal-datum-vertical-datum-and-resolution-a-usgs-digital-elevation-model)
- For emission time `t`, define `q = aircraft_position(t) - microphone_position`, `R = ||q||`, and `v_r = dot(aircraft_velocity(t), q / R)`. Positive `v_r` means the aircraft is receding. Using a constant sound speed `c`, initially about 343 m/s, compute `heard_time = t + R/c` and `heard_frequency = emitted_frequency * c/(c + v_r)`. Generate samples on the emission timeline and interpolate onto the audio timeline. The travel time varies across the pass, so apply it to every sample. For the closest point of approach (CPA), minimize the 3D range and add its own propagation delay to get the heard CPA. [Experimental study on delay and Doppler in aircraft acoustics](https://upcommons.upc.edu/bitstream/handle/2117/102818/Proof-AESCTE_3491.pdf?isAllowed=y&sequence=1)
- Verify the model with a synthetic straight flyby. Approaching samples should shift up, receding samples should shift down, and the emitted frequency should occur at the heard CPA for an interior smooth minimum. Then overlay the model on the real benchmark at its known microphone position. Investigate timing, track gaps, harmonics, and height reference if that overlay misses before searching over locations.

### 4. Recover a location from one timed flyover

- Hide the exact microphone coordinates. Search inside a regional bounding box over flights with positions near the recording’s UTC window. Lay a coarse grid in metres. Use observed speed and slant-distance bounds to reject improbable candidates, and keep flights of unknown type unless there is a separate reason to exclude them.
- At each remaining point, score normalized spectrogram energy along the predicted ridge, using interpolation between bins. Start with mean ridge energy relative to nearby off-ridge bins, minimum overlap, and a small sweep of emitted frequency and clock offset within measured uncertainty. A manually traced ridge can also be scored with robust frequency residuals when the signal is faint. Apply the same overlap rules to every candidate.
- Keep the best point per flight for comparison and retain neighboring points for the footprint. Refine the best clusters locally, for example from a 200 m grid to 100 m and then 50 m. Export a CSV, GeoJSON, and overlays of the winner and runner-up. The first acceptance target is the correct flight and a top cluster within a predeclared tolerance such as 250 m on one clean regional benchmark. Publish the measured error and any competing clusters.

### 5. Recover a location from two flyovers with an unknown start time

- Add a second marked event from the same continuous recording. Use the difference between observed CPA times, with an uncertainty derived from both ridge fits. The video’s approximately 920 s gap and its timing tolerance are specific to that clip. Generate candidate flight pairs and points where both events satisfy the broad speed and range bounds and the **heard** CPA separation matches the observed gap. For regional runs, a grid with sorted heard-event lists is enough to start. Pad the candidate date range for local dates that straddle UTC midnight. See the demo at [03:30–12:55](https://www.youtube.com/watch?v=UytYrhYLOKI&t=210s).
- Compare both predicted curves on the same audio timeline. Sweep **one shared recording-start offset** and allow each event its own emitted frequency. Each event’s position relative to the other follows the flight geometry. Keep individual event scores, enforce support from both ridges, and group results by ordered flight pair before ranking the best point from each. See the demo at [14:10–22:41](https://www.youtube.com/watch?v=UytYrhYLOKI&t=850s).
- Add the video’s quiet-interval idea after the baseline works. Apply a soft penalty when the candidate predicts an intervening flyover that should have left a visible ridge in a clean part of the recording. A missing ridge can result from masking, recording gain, or an aircraft that produced little usable tonal energy. If a third curve is available, reserve it for corroboration and check that it fits the same clock and location.

### 6. Make the results trustworthy before expanding the search

- Test a known positive, noise-only audio, a search box that excludes the true location, and a deliberately broken time gap. Compare a no-delay model with the propagation-aware model. Record true flight or pair rank, distance from the reference point, cluster size, score gaps, usable ridge coverage, runtime, and peak memory. Label a result `ambiguous` when separated clusters fit similarly and `insufficient evidence` when the audio or tracks fail basic quality checks. Calibrate any numerical confidence against held-out positives and decoys before displaying it.
- Test wind and sound-speed sensitivity, variation in propeller RPM, track dropouts, and clips with cuts. A 50 m grid is a sampling choice. Report an area when the score surface is broad or shifts substantially under modest changes to assumptions.
- Expand from region to state to country only after the regional tests are repeatable. Cache normalized flight tracks and coarse matches, partition flight data by time and spatial tile, join compatible track segments before building local candidate grids, and run full curve scoring only on survivors. Measure the count and time at each stage before tuning. A lightweight GUI or automatic event detector can follow once the CLI produces reproducible results.

## Data passed between stages

| File | Minimum contents |
| --- | --- |
| `recording.json` | Source file identifier, decoded channel, sample rate, optional UTC audio start and uncertainty, discontinuities |
| `events.json` | Time window in clip seconds, traced `(time_s, frequency_hz)` points, harmonic number if known, fitted CPA time and speed/range bounds |
| `tracks.csv` or `tracks.parquet` | Aircraft and segment IDs, UTC sample time, latitude, longitude, altitude in metres with source and reference, optional speed and type |
| `results.csv` and `results.geojson` | Candidate coordinates, flight IDs, event scores, combined score, shared clock offset, cluster ID, verdict |
| `overlays/` | Measured and predicted ridges for leading candidates with labeled time and frequency axes |

## Estimated effort

Allow one or two focused sessions for the benchmark and first known-position overlay once the files are available. Plan roughly two to four more sessions for a timed regional prototype, and another two to four for locked two-event scoring and negative controls. Country-scale indexing and tuning depend on data availability and benchmark results. These are planning estimates for a new implementation.
